# Tech Spec 기술 명세 생성

프로젝트의 requirements와 prd 문서를 분석하여 `3_tech_spec.md` 파일을 자동 생성한다.

## 실행 조건

- 프로젝트 루트: 이 파일 기준 `../../`
- 오늘 날짜를 `date +%Y-%m-%d` 로 구한다
- 템플릿 경로: `template/tech_spec.md`

## 실행 절차

### 1단계: 프로젝트 선택

`workspace/3_projects/` 아래 모든 프로젝트 폴더를 탐색한다.

각 프로젝트의 첫 번째 `.md` 파일에서 YAML frontmatter를 읽어 메타데이터를 수집한다.

```
📋 현재 프로젝트 목록

 #  | 프로젝트명                  | 상태          | 생성일      | 마감일
----+----------------------------+--------------+------------+-----------
 1  | 2026-03-01_todo_list       | discovery    | 2026-03-01 | 2026-03-30
 2  | 2026-03-10_auth_service    | discovery    | 2026-03-10 | 2026-04-15

Tech Spec을 생성할 프로젝트 번호를 선택해주세요.
```

프로젝트가 없으면:
```
📋 workspace/3_projects/에 프로젝트가 없습니다.
```
출력 후 종료한다.

### 2단계: 입력 문서 확인

선택된 프로젝트 폴더에서 아래 파일의 존재 여부를 확인한다:
- `1_requirements.md` — 요구사항, 내부 정보
- `2_prd.md` — 기획 문서

확인 결과를 출력한다:

```
📄 입력 문서 확인

  ✅ 1_requirements.md
  ✅ 2_prd.md
```

- 2개 모두 없으면 최소 1개 이상 문서를 먼저 작성하라고 안내 후 종료한다.
- 있는 파일들의 내용을 모두 읽는다.

### 3단계: 문서 분석 및 Tech Spec 초안 제안

읽은 문서를 분석하여 tech_spec의 핵심 섹션을 사용자에게 제안한다:

```
🔍 문서 분석 결과

📌 과제 명: {추론한 과제명}

📝 요약:
- {2줄 요약}

🎯 목표:
- {예상 결과}

🚫 목표가 아닌것:
- {범위 밖 항목}

📋 계획 (접근 방식):
- {접근 방식 요약}

수정할 내용이 있으면 말씀해주세요. 없으면 Y를 입력해주세요.
```

- 사용자가 수정을 요청하면 반영 후 다시 제안한다.
- 사용자가 승인하면 다음 단계로 진행한다.

### 4단계: Tech Spec 파일 생성

`template/tech_spec.md` 를 기반으로 `3_tech_spec.md`를 생성한다.

YAML frontmatter는 프로젝트의 기존 frontmatter 값을 따른다 (created, deadline, status, tags).

#### 섹션별 작성 규칙

**과제 명:**
- 프로젝트명과 관련 링크를 기재한다.
- prd에 Confluence 링크가 있으면 포함한다.
- requirements에 JIRA 링크가 있으면 포함한다.

**요약:**
- prd와 requirements를 기반으로 2줄 이내로 작성한다.

**배경:**
- requirements의 "요구사항" 섹션과 prd의 배경 정보를 조합한다.
- 왜 이 과제가 필요한지, 이전 시도가 있었는지를 정리한다.

**목표 / 목표가 아닌것:**
- prd의 목표를 기반으로 작성한다.
- requirements에서 명시적으로 제외된 사항이 있으면 "목표가 아닌것"에 포함한다.

**계획:**
- 기술적 접근 방식을 작성한다.
- requirements의 "개발 진행시 필요한 지식"과 "내부 정보"를 반영한다.
- 가능하면 mermaid로 시퀀스 다이어그램이나 ERD를 포함한다.

**고려사항:**
- 분석 과정에서 발견한 트레이드오프나 제외 결정 사항을 기록한다.

**마일스톤:**
- deadline 기반으로 대략적 마일스톤을 제안한다.
- 사용자가 수정할 수 있도록 초안으로 작성한다.

**참고:**
- 입력 문서 경로와 외부 링크를 정리한다.

#### 파일 충돌 처리

`3_tech_spec.md`가 이미 존재하면:
```
⚠️ 3_tech_spec.md가 이미 존재합니다.
1. 기존 내용에 보강 (빈 섹션만 채움)
2. 덮어쓰기
3. 건너뛰기
```

- "기존 내용에 보강" 선택 시: 기존 파일을 읽고, 내용이 비어있는 섹션만 채운다. 이미 작성된 섹션은 건드리지 않는다.

### 5단계: 결과 보고

```
✅ Tech Spec 생성 완료

📁 workspace/3_projects/2026-03-01_todo_list/
  ✅ 3_tech_spec.md 생성

  작성된 섹션: 과제명, 요약, 배경, 목표, 계획, 마일스톤
  빈 섹션: 고려사항, 참고 (추후 보완 필요)
```
